Runner activation env builder (location TBD by reading codebase — likely tools/run_recipe.py::build_activation_substitutions or services/runner_bridge.py near the docker run/create call):
```python
if recipe.get("runtime", {}).get("via_proxy"):
    process_env.pop("OPENROUTER_API_KEY", None)
    process_env.pop("ANTHROPIC_API_KEY", None)
    process_env.pop("OPENAI_API_KEY", None)
    api_var = recipe["runtime"]["process_env"]["api_key"]  # "OPENROUTER_API_KEY" etc.
    proxy_base = "http://api_server:8000/v1/llm/forward"
    placeholder = f"ap-proxy-{inapp_auth_token}"
    # AMD-09 — bots that read provider config from a JSON file (nanobot via
    # ~/.nanobot/config.json providers.openrouter.api_base) need the proxy
    # URL accessible to a heredoc sh-expansion. AP_PROXY_BASE_URL is the
    # canonical name; recipes use ${AP_PROXY_BASE_URL:-https://openrouter.ai/api/v1}
    # in the JSON heredoc so the legacy path also works when via_proxy=false.
    process_env["AP_PROXY_BASE_URL"] = proxy_base
    if api_var in ("OPENROUTER_API_KEY", "OPENAI_API_KEY"):
        process_env["OPENAI_BASE_URL"] = proxy_base
        process_env["OPENAI_API_KEY"] = placeholder
    elif api_var == "ANTHROPIC_API_KEY":
        process_env["ANTHROPIC_BASE_URL"] = proxy_base
        process_env["ANTHROPIC_API_KEY"] = placeholder
    else:
        raise ValueError(f"recipe {recipe.name}: via_proxy=true requires recognized api_key env var, got {api_var!r}")
```
